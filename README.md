# QRCommunication

画面に表示した QR コードをカメラで連続スキャンして、テキスト・ファイル・
GitHub リポジトリを機器間で転送するブラウザアプリです。サーバーを介さず、
2 台のブラウザ（送信側・受信側）だけでデータをやり取りします。

## 特徴

- **サーバーレス**: バックエンドなし。送信側は QR コードを連続表示し、
  受信側はカメラでそれを読み取るだけでデータを復元します。
- **3 つの送信モード**: テキスト／ファイル／GitHub リポジトリ
  （`owner/repo[@ref]` や URL を指定すると `api.github.com` から
  取得して送信、公開リポジトリのみ対応）。
- **リポジトリの送信ファイル選択**: リポジトリ送信では「ファイル一覧を
  取得」でツリーだけ先に読み込み、送るファイルをチェックボックスで選べます。
  パスでの絞り込みと、選択に応じた合計サイズ・推定転送時間の表示付き。
  並び順は「パス順」「更新日時（新しい順／古い順）」から選べます。更新日時は
  ブランチの履歴（first-parent）を新しい方から辿って各ファイルの最終変更
  コミット日時を求めます。API の上限（未認証 60req/hour）を考え、辿るのは
  最大 40 リクエストまでで、それより古いファイルは「日付不明」として末尾に並びます。
  一覧を取得せずに開始した場合は従来どおり全ファイルを送ります。
- **複数ファイルの送信**: ファイル送信は複数選択できます。2件以上を選ぶと
  zip にまとめて1回で送ります（1件のときは zip で包まずそのまま送信）。
  選び直すたびに追加されていくので、別のフォルダからも足せます。不要な
  ものは行ごとに外せます。
- **範囲指定再送**: 受信側で欠損したチャンク番号だけを送信側に伝えて
  再送できます。
- **画像の縮小**: ファイル送信で画像を選ぶと（複数選択に混ざっていても）、縦横の縮小率を
  75%／50%／25%／無 から選べます（画素数は 75%→約56%、50%→25%、
  25%→約6%）。WebP、書き出せない環境では JPEG に再エンコードします。
  縮小後の解像度・サイズ・推定転送時間をその場で表示するので、送り始める
  前に確認できます。元画像に対する比率なので、極端に小さい画像を 25% に
  すると実用に耐えない解像度になる点に注意してください。
- **Wake Lock 対応**: QR 表示中・カメラスキャン中・QRブリッジ表示中は、
  送信側・受信側どちらの端末も画面がスリープしないよう抑止します。
  抑止できない環境（HTTPS 以外、iOS 16.4 未満の Safari、低電力モードなど）
  では画面上部に警告を表示するので、端末の自動ロックを手動でオフにして
  ください。
- **効率のよい転送形式**: 送るデータは deflate で圧縮し（テキストや未圧縮の
  ファイルは 1/2〜1/3 程度に）、QR の英数字モードで base45（RFC 9285）として
  載せます。従来の base64 + バイトモードより、同じ大きさの QR に約3割多く
  載ります。セッションIDは中身から決まるので、送信側を止めて FPS などを
  変えて再開しても、受信側の途中経過はそのまま引き継がれます。復元時には
  中身を検証し、別の送信のQRが混ざった場合はエラーにします。
  旧バージョンの送信側（QRT2 形式）からも受信できます。旧バージョンの
  受信側は新形式を読めないので、受信側を更新できないときは「設定」→
  「送信形式」で「旧形式（互換）」を選んでください（圧縮なし・base64 の
  ため枚数は 1.3〜4 倍ほどに増えます）。受信側の画面下の「最終更新」が
  2026-09-28 以前なら旧バージョンです。
- **見やすい送信画面**: 送信中は入力欄を畳んで要約だけを表示し、QR が
  1画面に収まるようにします。「⛶」で QR を画面いっぱいに表示できます。
- **受信の完了処理**: 全チャンクがそろうとカメラを自動で止め、端末を
  振動させて結果までスクロールします（その後に映った別のQRで結果が
  消えることはありません）。受信ペース（枚/秒）も表示します。
- **高速な読み取り**: 端末内蔵のQRデコーダ（BarcodeDetector）があれば
  それを使い、無い端末では jsQR を複数の Web Worker で並列に動かします。
  カメラ映像の右下に1秒あたりの解析回数を表示するので、送信側の FPS は
  この値より十分低く（目安: 半分程度）設定すると取りこぼしが減ります。
- **設定を保存**: チャンクサイズ・FPS・誤り訂正レベル・QR バージョン・
  セルサイズ・カメラ解像度などを細かく調整でき、`localStorage` に保存
  されます。外部への送信は GitHub リポジトリ取得時のみです。

### 未受信チャンク番号の伝達（QRブリッジ）

ネットワークで繋がっていない2台間で、受信側が検出した未受信チャンク範囲を
送信側に伝えるための機能です。

- 受信側で「📱 QRで送る」を押すと、未受信範囲を小さなQRとして表示します。
- 送信側で「📷 QRで受け取る」を押すとカメラが起動し、そのQRを読み取って
  範囲指定欄に自動入力します（読み取り後は「反映」を押して適用）。
- 大きいファイルで未受信番号が多い場合は、番号リストを圧縮したうえで
  複数枚のQRに分割し、自動で切り替えて表示します。送信側は全枚数を
  読み終えた時点で範囲指定欄に入力します（読み取り中は「k / n 枚」を表示）。
- メインの送受信ループとは別のカメラ／キャンバスを使うため、やり取りして
  いる間も両端末のセッション（送信ループ・受信スキャン）は途切れません。
- カメラの起動には動作要件と同じく HTTPS または `http://localhost` が
  必要です。LAN内のIPアドレス（`http://192.168.x.x:...` など）で開いている
  場合はカメラAPIがブロックされ動作しません。

うまくいかない場合は、未受信のチャンク番号を目視で確認し、範囲指定欄に
手入力して再送してください。

## 使い方

1. **送信側**: 「送信」タブでテキスト／ファイル／GitHub リポジトリを選び、
   「QR表示開始」を押します。QR コードが連続的に切り替わって表示されます。
2. **受信側**: 「受信」タブで「カメラ開始」を押し、送信側の画面を映します。
   全チャンクを受信するとカメラが止まり、テキストのコピーやファイルの
   ダウンロードができます。
3. 送信中に画面を離れても、QR は最初から繰り返し表示されるため、途中から
   スキャンを始めても問題ありません。
4. 受信で欠けたチャンクがある場合は、未受信番号を確認し、送信側の
   「範囲指定」欄にその範囲を入力して「反映」を押すと、該当分だけ
   再送されます。
5. 「設定」タブでチャンクサイズ・FPS・誤り訂正レベルなどを調整すると、
   転送速度や読み取り精度を環境に合わせて最適化できます。

## 動作要件

カメラ（`getUserMedia`）を使うため、`https://` または `http://localhost`
での配信が必要です。それ以外の URL ではカメラ起動に失敗する可能性が
あります。

## 使用ライブラリ

`vendor/` 以下にバンドルしています。ビルドは不要で、`index.html` を
直接開くだけで動作します。

- [qrcode-generator](vendor/qrcode-generator.js) (MIT)
- [jsQR](vendor/jsQR.js) (Apache-2.0)
- [fflate](vendor/fflate.min.js) (MIT)
